# BDS 启动项与 efisp 配置存储

本文说明 super-fastboot BDS（`build/BDS.efi`）如何保存启动项、启动项从何而来，以及按什么顺序尝试启动。

## efisp 分区

`efisp` GPT 分区包含两部分：

| 区间（取自 GPT 分区项，`EndingLBA` 为闭区间） | 内容 |
| --- | --- |
| `StartingLBA` 至 `StartingLBA + 1 MiB / BlockSize - 1` | `BDS.efi`，普通 PE 镜像 |
| `StartingLBA + 1 MiB / BlockSize` 至 `EndingLBA` | 唯一的 FAT 卷（配置容器），无分区表 |

- 构建不会把 `BDS.efi` 补齐到 1 MiB。镜像达到 1 MiB 时 `make build` 直接失败。
- 刷写 BDS 只写文件本身长度，例如 `dd if=BDS.efi of=<efisp> bs=4096 conv=notrunc,fsync`。按文件长度写入不会触及其后的容器。
- `fastboot erase efisp` 或写入整分区镜像会清空容器，下次启动时 BDS 会重新格式化出一个空容器。
- BDS 只通过一个限定在该 LBA 区间内的 512 字节 Block I/O 访问容器。经由它的写入不可能落在 1 MiB 之前或 `EndingLBA` 之后。

每次启动 BDS 都会挂载容器。若 FAT 驱动无法挂载，且首扇区不是可用的 FAT 引导扇区，BDS 会按容量现场格式化为 FAT12、FAT16 或 FAT32，然后重新挂载。仍然失败时，BDS 不带持久存储继续启动。已有看起来有效的 FAT 引导扇区的容器即使挂载失败也不会被自动格式化。

## 启动项

持久化的启动项列表是容器内的 `CONFIG\ENTRIES.CFG`。每行一个启动项，行序即启动尝试顺序。无人操作时按此顺序尝试；Android 启动方式只自动尝试一次，失败后不会继续尝试另一种状态或备份。该文件在运行时生成，不随任何包分发。

### 行格式

```
<名称>:[(<磁盘>,<分区>)]<卷内绝对路径> [参数]
```

```
Android Tools\Reboot Tools:(1,1)\efisp\tools\RebootTools.efi
Android Tools\Reboot Tools:\efisp\tools\RebootTools.efi
```

- 名称中的 `\` 表示分级菜单。上例显示为 "Android Tools >"，其下是 "Reboot Tools"。
- `(d,p)` 表示 UEFI 枚举到的第 d 块整盘上的第 p 个分区。两者都从 0 开始，p 等于 GPT 分区项序号减一。
- 不写 `(d,p)` 时，路径位于提供当前 ENTRIES.CFG 的那个卷上。
- 路径中可以用 `/` 代替 `\`。
- 名称中任一级以 `$` 开头表示隐藏项：它仍是普通启动项，保留在启动顺序中的位置，按正常流程加载并启动（参数照常传递），只是启动菜单不显示它。驱动型镜像 StartImage 返回后继续下一项；应用型镜像就在自己的位置运行。使用 BOOT_CERTS 时同样验签；失败按普通项规则处理（非 PE 镜像删除，其它错误保留并继续）。启动项管理/顺序列表仍会列出它。
- 路径后第一个空白之后的内容作为 LoadOptions 传给镜像。
- 空行和 `#` 开头的行会被忽略。
- 旧的 `$`/`%` 行首标记、`SFB1|...` 记录和卷标匹配均已删除；`$` 现在只用于标记启动菜单不显示的启动项。

### 启动项来源

扫描会遍历所有属于 GPT 分区的 FAT 和 ext4 卷：

1. 卷上存在 `\EFI\BOOT\BOOTAA64.EFI` 时，加入一个以卷标加地址命名的启动项，例如 `EFIBOOT (0,2)`。BDS 自身所在的镜像会被跳过。
2. 卷根目录有 `ENTRIES.CFG` 时，其中文件确实存在的每一行都会加入。未写 `(d,p)` 的行记录为该卷的地址。

随后与已存储的列表同步：

- 文件已不存在的已存储项被删除。
- 其余项保持原有顺序。
- 新发现的项追加到末尾。

结果以原子方式写回 `CONFIG\ENTRIES.CFG`：先写临时文件并刷盘，再删除旧文件，把新文件改名到位，最后再刷盘一次。

### 开机流程

1. 读取 `CONFIG\ENTRIES.CFG`。文件不存在或存储不可用时得到空列表。
2. 列表为空时扫描、同步并写盘。
3. 仍为空时进入启动菜单。
4. 按下菜单键（音量上）时扫描、同步并写盘，然后进入菜单。
5. 否则按顺序尝试启动项（隐藏 `$` 项也在自己的位置正常参与）。Android 方式只尝试第一项，其余 Android 方式和备份留给菜单手动选择，避免失败回退时绕过状态切换确认。LoadImage 判定文件不是 PE/COFF 镜像或架构不匹配时，删除该项并重新写盘。文件缺失、安全校验拒绝、内存不足等其它错误保留该项，继续尝试后续独立 EFI 项。
6. 全部失败时进入启动菜单。

启动菜单每次打开时也会重新扫描并写盘。

### Advanced 菜单

- **Boot Entries Priority**：选中一项，用音量上和音量下移动，按电源键确认。新顺序会写盘。隐藏项也和其他启动项一样列出。
- **Boot Entries Management**：选中一项并确认删除，列表随即写盘。隐藏项也会列出，可正常删除。
- **USB Mass Storage > Export Config Store**：卸载容器，并在其外层合成一份 GPT，唯一的 ESP 类型分区恰好覆盖容器，宿主机看到的是普通 FAT 分区。导出结束后重新挂载，并重新读取存储列表，以防宿主机修改过它。

被删除的项如果其文件仍在某个卷上，下次扫描时会被重新加入。扫描发生在列表为空、按下菜单键或打开菜单时。要彻底去掉它，请删除该文件或对应的 `ENTRIES.CFG` 行。

## 启动选项

### 启动方式确认与勾选

手动选择假回锁、真实状态或备份入口时，先显示数据解密和格式化风险，再要求按电源键确认三次。每步间隔一秒并清理按键缓冲；任一步按音量键均可取消。确认完成前不加载镜像，也不保存启动方式。文件选择器启动这些文件时同样需要确认。

假回锁和真实状态在确认后保存：与启动顺序中首个常规 Android 方式交换位置，其他项的位置保持不变。菜单用 `✓` 标记当前默认方式，移动光标不改变勾选。备份和未加入列表的临时入口不覆盖默认方式；保存失败会显示错误并中止启动。勾选表示已配置的启动方式，独立于设备的真实 BL 锁状态。

BL 锁状态工具的锁定、解锁和 Critical 状态写入同样需要三次确认；ARB 重置保留五次确认。更新确认界面需要同时更新 BDS 和 BLTools。

### 开关设置

进入启动菜单的 **启动选项**，用音量键选择，用电源键切换：

已开启的选项显示 `✓`，关闭后移除。标记在保存成功后更新；保存失败时重新读取配置。

- **开机提示**：默认关闭。开启后，在真实 BL 已解锁时恢复原厂 Orange State 解锁警告。
- **修复官方 FB**：默认开启。启动 Android 前，按参考项目的已知 OPlus 验证分支布局应用 Fastboot 修复。关闭时保留原始验证分支。
- **启动 / 菜单提示** 默认关闭。启动页只显示启动项名称，例如“Android（假回锁）”。选择子菜单后直接显示菜单内容。开启后，启动页还会显示“正在启动…”和设备的真实 BL 状态，进入子菜单时会显示“正在进入…”。

菜单标题同时显示设备持久化的真实锁状态。主菜单显示“假回锁-已解锁”或“假回锁-未解锁”，子菜单显示对应标题和解锁状态。读取失败时在标题中显示错误码。菜单按屏幕可用高度计算列表行数，空间不足时滚动，并显示剩余项数。

设置保存在配置容器的 `CONFIG\BOOTOPTIONS.CFG`，格式为 `SFBO2|<开机提示 0/1>|<修复官方 FB 0/1>|<启动 / 菜单提示 0/1>`。已有 `SFBO2` 配置沿用三个开关的保存值。旧版 `SFBO1` 配置沿用前两个开关，启动和菜单提示默认关闭。文件不存在时使用默认值，文件损坏或保存失败时显示错误。开机提示和 FB 修复用于下一次启动 Android，包括假回锁、真实状态和备份入口，不影响独立 EFI 工具。自带 Fastboot 的界面名称统一为 **SuperFastboot**。

补丁仅修改本次启动的内存副本，不改写磁盘上的 EFI 文件。有 `BOOT_CERTS` 时，先验证磁盘原件，再为当前加载操作复用验签结果。

模块和三平台工具包会使用 `--defer-fastboot` 生成保留原始 Fastboot 分支的 loader。旧版已经永久应用 Fastboot 补丁的 loader 无法准确还原原始 W/X 条件分支；要关闭修复，需从原始 ABL 重新生成 `boot.efi` 和 `boot_normal.efi`。仅更新 BDS/Tools 不会重新生成这两个文件。没有该验证分支的 ABL 保持原路径，不能据此认定其官方 Fastboot 已验证可用。

## 安全证书

容器中还存放安全证书类，以 X.509 DER（`.cer`）文件、按目录分类：

| 目录 | 类别 | 非空时的效果 |
| --- | --- | --- |
| `AUTH_CERTS` | A 类 —— fastboot 授权 | 进入锁定模式，直到挑战应答验证通过 |
| `BOOT_CERTS` | B 类 —— EFI 代码签名 | 所有被启动的 EFI 必须带可验证的签名 |

两个功能完全由证书驱动：目录为空（或不存在）即关闭该功能，BDS 行为与之前完全一致。完整模型（挑战协议、fastboot 命令门控、顶层仓库 `tools/sfbsec/` 下的签名工具）见 [sfb-security.md](sfb-security.md)。
